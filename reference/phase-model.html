Phase Model

The phase primitive, its statuses, and the success rules. Print this.

The primitive

with run.phase(PhaseParams(
        name="build",              # short, unique within the run
        kind="agent",              # engineer | agent | code
        owner="builder",           # human name, "git", or agent from config
        description="...",         # REQUIRED, must not echo the name
        retries=1,                 # agent phases only: gate-correction rounds
)) as ph:
    ph.log(input=prompt)           # engineer phases
    env = ph.call(AgentCall(...))  # agent phases only

Statuses

StatusSet when
queueddeclared but not started
runningat phase open, before the body runs
successthe with block exits without raising
failthe default, and left in place by any raise

Success rules

  • All phases: clean exit from the with block.
  • Agent phases, additionally: final JSON parses against output_type, and every gate green.
  • The run: phases_ok AND accepted. Both, via one run.finish(accepted=..., reason=...) call that settles db status, banner, and exit code together.
  • Exit code is 0 when ok, else 1.

Phase kinds

KindLaneBody
engineerhumanph.log(); an input= payload also records the session request
agentagentph.call(); anything else raises RuntimeError
codedeterministicplain Python: git, migrations, file moves

Rule: a code step never hides inside an agent phase. If it happened, it has a phase.

Gotchas

  • description is validated at construction. Blank, or a restatement of name, raises before the phase opens.
  • More than four parameters to a function means pass one object instead. PhaseParams and AgentCall are the pattern.
  • A joined run (--adw-id) continues the phase sequence rather than restarting at 1.
  • Phase success ≠ run success. A test phase that ran a red suite is a successful phase.
